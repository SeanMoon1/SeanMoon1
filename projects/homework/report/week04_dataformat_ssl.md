# 데이터 교환 포맷 및 시리얼라이징 이해

## 데이터 포맷이란?

    시스템이 자료(데이터)를 입출력하거나 저장할 때의 데이터 구조,형식 또는 크기를 의미한다.

### XML, JSON, YAML 비교

- 1. XML

  - eXtensible Markup Language의 약자, 다목적 마크업 언어이다. 태그등을 사용하여 데이터의 구조를 기술하는 언어로, 가장 쉽게 접할 수 있는 마크업 언어는 HMTL이다.
    고유한 문법이 있어 소프트웨어/하드웨어에 대하여 독립적으로 데이터를 처리할 수 있고, 트리 계층구조를 지니고 있다.
    데이터에 의미를 부여하는 메타데이터를 선언할 수 있어 정보 표현에 매우 효과적이지만, 실제 전송하는 데이터에 비해 메타데이터의 크기가 더 커질 수 있다는 단점이 있고, JSON 등장 이후엔 자주 사용되지 않는다.

  ```XML
  <student>
   <id="1">
       <name>김철수</name>
       <age>18</age>
       <hobby>농구</hobby>
  </id>
  </student>

  ```

- 2. Json
  - JavaScript Object Notation의 약자, '키(혹은 속성)-값' 형태의 쌍으로 이루어진 데이터 객체를 전달하기 위해 인간이 읽기 쉬운 텍스트 형태를 사용하는 개방형 표준 포맷이다. 서버-클라이언트간 통신을 위해 현재 주목받고 있는 XML을 대체하는 주요 데이터 포맷이다.
    자료 종류에 따른 큰 제한이 없어 프로그래밍시 변수의 값을 표현하는데 적합하게 사용되고 있다. 보통은 순서를 나타내는 인덱스 값을 기준으로 데이터를 찾는 형태로 구성 및 사용된다. 콤마나 쌍따옴표 등의 누락, 잘못된 중괄호의 위치 등 문법 오류에 취약하다는 단점이 있지만, 모양과 규칙이 단순하여 타 언어에서도 구현하기가 쉽다는 장점에 의해 REST API에서 가장 많이 사용된다.

```JSON
{
    "student": [
        {
            "id":1,
            "name":"김철수",
            "age":18,
            "hobby":"농구"
        }
    ]
}

```

- 3. YAML
  - YAML은 구성 파일을 작성하는 데 일반적으로 사용되며 사람이 읽을 수 있는 다목적 데이터 직렬화 언어다.
    YAML Ain't Markup Language 혹은 Yet Another Markup Language 의 약어로 마크업 언어가 아닌 데이터를 위한 언어라는 점을 강조하는 의미가 있다.
    YAML은 기본적으로 단순성과 가독성을 염두에 두고 설계되었다. 들여쓰기, 키-값 쌍, 직관적인 규칙을 기반으로 최소한의 깔끔한 구문을 사용한다. 이러한 접근 방식을 통해 개발자와 사용자는 복잡한 데이터 구조를 자연어와 유사하고 한눈에 이해하기 쉬운 형식으로 표현할 수 있다.

```YAML
name: "홍길동"
age: 30
address:
  city: "서울"
  street: "강남대로"
  zip_code: "12345"
  phone:
    - "010-1234-5678"
    - "02-111-2222"
is_active: true

```

- ## 시리얼라이징(직렬화)이란?

  - 데이터 시리얼라이제이션이란, 어떤 환경의 데이터 구조를 다른 환경에 전송 및 저장하기 위해 나중에 재구성할 수 있는 바이트의 포맷으로 변환하는 과정을 말합니다. 반대로, 일련의 바이트로 부터 데이터 구조를 추출하는 일은 역직렬화(Deserialization)라고 합니다.
    더 간단하게 한줄로 표현하면 객체를 데이터스트림으로 만드는것이다.

- ## https, SSL 인증서 기초

  - HTTPS는 HTTP 프로토콜에 보안(SSL/TLS) 프로토콜을 추가하여 안전하게 데이터를 주고받는 방식입니다. SSL 인증서는 서버의 신원을 확인하고 데이터 전송을 암호화하는 데 사용되는 디지털 증명서입니다. SSL 인증서가 없으면 HTTPS 연결이 불가능하며, 웹사이트의 신뢰성을 보장하기 위해 반드시 필요합니다.

- ### HTTPS (Hypertext Transfer Protocol Secure):

  - HTTP 프로토콜에 SSL/TLS 프로토콜을 결합하여 웹 통신의 보안을 강화한 방식입니다.
    데이터를 암호화하여 전송하므로 중간에서 데이터가 가로채지더라도 내용을 확인할 수 없습니다.
    주소창에 자물쇠 모양 아이콘과 "https://"로 시작하는 URL을 통해 확인할 수 있습니다.

- ### SSL 인증서 (Secure Sockets Layer Certificate):

  - 서버의 신원을 확인하고 데이터를 암호화하는 데 사용되는 디지털 문서입니다.
    인증 기관(CA)에서 발급하며, 서버의 공개 키와 서버 정보, 유효 기간 등을 포함합니다.
    클라이언트(브라우저)는 SSL 인증서를 통해 서버의 신뢰성을 검증하고 안전하게 통신할 수 있습니다.

- ### HTTPS와 SSL 인증서의 관계:

  - 1. 클라이언트가 서버에 접속:
       브라우저가 웹 서버에 접속하면 서버는 자신의 SSL 인증서를 클라이언트에게 보냅니다.
  - 2. 인증서 검증:
       클라이언트는 인증서를 발급한 인증 기관(CA)이 신뢰할 수 있는 곳인지 확인합니다.
  - 3. 암호화 통신 시작:
       검증이 완료되면 클라이언트와 서버는 대칭키 암호화 방식으로 안전하게 데이터를 주고받습니다.
